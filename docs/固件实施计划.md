## 1. 四个关键决策

**① 8266 驱动：用 `8266demo` 里的官方源码，不用闭源 .lib**

`8266demo/Drivers/BSP/ATK_MW8266D/` 有完整源码（`atk_mw8266d.c` 419 行 + uart 167 行），AT 指令序列是正点原子验证过的，比 `AIOT_Device_STM32F103_WIFI` 里那个 `.lib` 强得多——那个库连源码都没有，出问题只能猜。

用法：**`atk_mw8266d.c` 原样编译，只把 `atk_mw8266d_uart.c` 换成我们自己的实现**（保持三个函数签名：`uart_init` / `uart_printf` / `uart_rx_get_frame`）。这样 `join_ap`、`connect_tcp_server`、`enter_unvarnished` 全部白拿。

驱动里已确认的关键行为：
- 透传流程 = `AT+CIPMODE=1` → `AT+CIPSEND` → 之后 UART 直通
- RST 引脚 = **PA4**
- `rx_get_frame_len()` 存在，长度语义可救

**② MQTT 自己写，但先在 PC 上测**

约 400 行：CONNECT / CONNACK / SUBSCRIBE / SUBACK / PUBLISH(收发) / PUBACK / PINGREQ / PINGRESP / DISCONNECT。纯 C 无依赖，用 gcc 在 PC 上先连本机 Broker 跑通，再原样搬到 Keil。这样"固件写完发现协议错了"的风险归零。

**③ 时间基准：snapshot 的 `issuedAt` 授时，未授时拒绝一切 cmd**

无 RTC。收到验签通过的 snapshot 就用它的 `issuedAt` 校准，之后 SysTick 累加。没校准前所有 cmd 回 `ERR_NOTIME`、屏幕显示 `NO TIME`（fail-closed）。

⚠️ **上电顺序**：先起 Broker 和后端，**再给板子上电**。因为 retained 快照由后端每分钟 `refreshAll()` 刷新，板子先上电会等最多 60 秒才有时间基准。

**④ 锁与蜂鸣全非阻塞**

`lockOpenUntilTick` 变量 + 主循环比较，绝不 `HAL_Delay(3000)`——那会阻塞 MQTT 收包、拖垮心跳、喂不了狗。

## 4. 协议契约速查

| 方向 | 主题 | QoS | Retained | 消息类型 |
|---|---|---|---|---|
| 后端 → 设备 | `room/{code}/snapshot` | 1 | **是** | `DISPLAY` |
| 后端 → 设备 | `room/{code}/cmd` | 1 | 否 | `UNLOCK` / `BUZZ` / `REMIND` / `CLEAR` |
| 设备 → 后端 | `room/{code}/ack` | 1 | 否 | `ACK` |
| 设备 → 后端 | `room/{code}/heartbeat` | 0 | 否 | `HEARTBEAT` |
| 设备 → 后端 | `room/{code}/event` | 1 | 否 | `EVENT` |

信封字段：`v | msgId | type | deviceCode | reservationId | issuedAt | expiresAt | payload | hmac`
canonical 串：`v|msgId|type|deviceCode|reservationId|issuedAt|expiresAt|payload`（空值参与为空串）
`payload` 是扁平串：`pulseMs=3000;reason=FIRST_CHECKIN`

**五步校验（顺序不可变）**

| # | 判据 | 失败回执 |
|---|---|---|
| 1 | `deviceCode` == 自身 | `ERR_DEVICE` |
| 2 | HMAC 匹配 | `ERR_HMAC` |
| 3 | `now < expiresAt`（缺字段也拒） | `ERR_EXPIRED` |
| 4 | `msgId` 不在最近 16 条 | `ERR_DUP` |
| 5 | `reservationId` == 屏上当前预约 | `ERR_BIND` |

失败也要回 ack——服务端靠它区分"没执行"和"消息丢了"。

**屏幕快照载荷**：`reservation=42;status=APPROVED;startsAt=…;endsAt=…;remain=57:48;code=4821`
`code` 只在签到窗口 `[开始, 开始+5min)` 内下发。

**账号**（`deploy/mosquitto/acl`）
设备：`room-a` / `room-a-secret`，只能读写 `room/ROOM-A-01/#`
设备号密钥：`ROOM-A-01` / `demo-secret-room-a-please-change`

## 6. 风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| 透传模式丢包 | 报文缺半截、`CLOSED` 后不重连 | MQTT 层自己做重传；检测到 `CLOSED` 就退出透传重新 AT |

| Broker 认证失败 | 一直 CONNACK=5 | 先 `mosquitto_sub` 用同一账号验证，再查设备侧 password 长度 |

### 7.2 过程中真正踩到的坑（都已修，写下来避免重犯）

1. **ORE 溢出会把 DMA 接收彻底停掉**
   模块启动时的乱码足以触发溢出，HAL 的错误处理里 `UART_EndRxTransfer()` 直接终止接收。
   之后串口寄存器看起来一切正常、发送也正常，就是收不到任何东西。
   修法：实现 `HAL_UART_ErrorCallback` 清标志，并在主循环重新挂接；`uart_rearm()`
   必须先 `HAL_UART_AbortReceive` 再 `ReceiveToIdle_DMA`，否则 `RxState` 不是 READY 时直接返回 BUSY 且静默失败。

2. **`AT+CIPSTART` 后不能立刻发下一条**
   模块回 `busy p...`，我们等 3 秒超时。修法：`CIPSTART` 后等 600 ms，`CIPSEND` 加三次退避重试。

3. **`ALREADY CONNECTED` 会被误判成连接成功**
   它含有 `CONNECT` 子串，`strstr` 直接命中。失败后不关连接还会留下僵尸 socket，
   越积越多（Broker 侧能看到多个 ESTABLISHED 但从不发 CONNECT）。
   修法：`CIPSTART` 前先 `AT+CIPCLOSE`，`CIPSEND` 失败时也补一次关闭。

4. **`CIPSEND` 的应答尾巴会污染 MQTT 流**
   等到 `>` 就返回，后面的 `\r\n` 留在环形缓冲里，被 MQTT 层当成报文头解析，表现成"连上就断"。
   修法：进入透传前 `ring_flush()`。

5. **只复位 MCU 时模块仍停在透传模式**
   烧录后（Reset and Run）MCU 复位，但模块还连着上一轮的 TCP，于是 `AT` 被当成数据转发走，
   永远收不到 `OK`。修法：`ESP_INIT` 状态先发 `+++` 把模块拉回 AT 模式。

6. **时间只能取自验签通过的快照，且只能向前校准**
   开机拿到的往往是 retained 快照，它可能是几十秒前发布的；把它的 `issuedAt` 当"现在"，
   设备时钟会永久慢"消息年龄"（实测 3 秒，最坏 60 秒），导致过期指令被放行。
   修法：每张快照都校准，但只在 `t > time_now()` 时生效，绝不回拨。

### 7.3 已知限制

- **不再拉 PA4 做硬复位**：实测拉低后主循环会卡死（SysTick 停止递增，串口只剩一行日志），
  怀疑模块复位瞬间把 3.3V 轨拉垮。模块随主板上电自己启动，正常流程不需要硬复位；
  万一模块真的挂了，**断电重启整板**即可恢复，不要靠反复复位去"救"。
- **`ERR_BIND` 只有正向路径被测到**：跨预约开锁需要屏幕上挂 A 预约、指令带 B 的预约号，
  手工造一条 cmd 即可验证，尚未执行。
- **界面为英文**：中文需按 `codetab.h` 的 `F16x16` 索引取模，容易错位，暂缓。
- 12V 锁尚未接线，`PB0` 的 3 秒脉冲只用万用表确认过。
