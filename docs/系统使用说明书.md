## 1. 系统组成

```
 手机浏览器                    笔记本（服务端）                      门禁终端
┌──────────┐   HTTP    ┌──────────────────────┐   MQTT    ┌───────────────────┐
│ 预约/签到 │ ────────> │ Spring Boot  :8080   │ ────────> │ ESP8266 (STA)     │
└──────────┘           │ MySQL 8.0    :3306   │  1883     │   ↕ USART3        │
                       │ Mosquitto    :1883   │           │ STM32F103ZET6     │
                       └──────────────────────┘           │  SSD1306 / 蜂鸣器  │
                            ▲                             │  PB0 → 12V 锁     │
                            └──── room/+/ack 回执 ────────┴───────────────────┘
```

| 角色 | 职责 |
|---|---|
| 后端 | 预约、审核、信用分、下发签名指令、收设备回执 |
| Broker | 消息中转，保留设备屏幕快照（retained） |
| 设备 | 验签、开锁、显示、回执、心跳 |
| 手机 | 学生端预约与签到；管理员端审批与规则 |

**关键设计**：设备不信任网络。每条指令都要过五关——设备号、HMAC、有效期、去重、绑定关系。
设备的时间也只能来自**验签通过的**快照，因此"先启动后端、再给板子上电"是硬性顺序。

## 2. 硬件连线

### 2.1 器件清单

| 器件 | 型号/规格 | 状态 |
|---|---|---|
| 主控板 | 正点原子 精英 V2 / STM32F103ZET6 | 已用 |
| WiFi 模块 | ATK-MW8266D（ESP8266） | 已用，插 U3 座 |
| 显示屏 | SSD1306 128×64，4 针 I2C | 已用，飞线到 PB6/PB7 |
| 蜂鸣器 | 板载有源蜂鸣器 | 已用，PB8 |
| 12V 电控锁 | — | **未接**，PB0 预留 |

### 2.2 接线表

**开发板自身（决定能不能用，先查这三项）**

| 项 | 正确状态 | 不对会怎样 |
|---|---|---|
| `USB_UART` Type-C | 接电脑（通信 + 主供电） | 没供电、串口无输出 |
| P3 跳线（USART1↔CH340） | **RXD、TXD 两个帽都在位** | printf 全无输出，极易误判成固件坏了 |
| BOOT0 | 0（从 Flash 启动） | 停在 bootloader，不跑程序 |

**SSD1306**

| 屏针脚 | 接到 | 注意 |
|---|---|---|
| VCC | 3.3V 排针 | **3.3V，不是 5V**，接错直接烧屏 |
| GND | 板 GND | 必须共地 |
| SCL | **PB6** | 与板载 24C02 共用 I2C1 |
| SDA | **PB7** | 同上 |

> 不要插板上的 P4 座——那是并行 OLED/摄像头接口（PD3/PG13），不是 I2C。
> 正常时 I2C 扫描能看到 `0x3C`（屏）和 `0x50`（24C02）。

**ESP8266**

插到 **U3**（1×6 座），断电插拔。供电和串口（PB10/PB11）都由座子提供，无需飞线。

**蜂鸣器与锁**

| 器件 | 接法 |
|---|---|
| 板载蜂鸣器 | 不用接线，PB8 高电平响 |
| 12V 锁（未接） | PB0 → MOSFET 栅极，线圈并 1N4007 续流，12V 独立电源仅与板共地 |

### 2.3 上电自检

1. 合上电源开关，蓝色 PWR 灯常亮
2. 量 3.3V 排针：3.2–3.4V；量 5V：约 5V
3. 稳压芯片微温正常，**烫手立刻断电**
4. 设备管理器出现 CH340 的 COM 口（本机是 **COM4**）

## 5. 设备的正常表现

### 5.1 串口关键字

```
[BOOT] HMAC selftest ... PASS     自检通过
[ESP ] state -> AT/WIFI/TCP       联网进度
[NET ] CONNACK ok                 MQTT 握手成功
[NET ] READY                      订阅完成，可以收指令
[NET ] time synced: 2026-11-27T21:40:32   已从快照授时
[NET ] SCREEN status=FREE         屏幕已更新
[ALIVE] t=120s esp=READY net=READY       每 5 秒一次，证明主循环活着
```

上电到 `[NET ] READY` 约 **9 秒**。

### 5.2 屏幕状态

| 显示 | 含义 | 触发条件 |
|---|---|---|
| `NO LINK` | 没连上 Broker | AT/WiFi/TCP/MQTT 任一未通 |
| `WAITING` | 连上了，但还没收到快照 | 后端没起 / 没发 |
| `FREE` + 时间 | 空闲 | 当前无预约 |
| `RESERVED` | 已预约未开始 | 下方显示 `starts in N min` |
| `CHECK IN` + 4 位码 | 签到窗口内 | 窗口是 `[开始, 开始+5min)` |
| `IN USE` + 倒计时 | 使用中 | 已签到 |
| `ENDING` | 最后 5 分钟 | 倒计时 ≤ 5:00 |

## 6. 演示流程（约 8 分钟）

### 6.1 演示前 15 分钟

1. 按第 4 节启动 MySQL / Mosquitto / 后端
2. **对 IP**（最容易翻车的一步）：

   ```powershell
   Get-NetIPAddress -AddressFamily IPv4 | Where-Object InterfaceAlias -eq WLAN
   ```

   与 `D:\code\WebHardware\Overall\App\app_config.h` 里的 `APP_BROKER_HOST` 比对。
   **不一致就必须改并重新烧录**（`python fw.py cycle 30`）。

3. 板子断电重启，确认屏幕显示 `FREE` + 当前时间
4. 数据库确认在线：

   ```powershell
   mysql -uroot -p****** -D db02 -e "SELECT device_code,online,last_heartbeat_at FROM t_device;"
   ```

### 6.2 动线

| 时间 | 动作 | 看点 |
|---|---|---|
| 0:00 | 指着屏幕讲三种数据来源 | 状态/剩余时间/签到码都来自一条签名快照 |
| 0:30 | `student01` 在排期板约下一格 15 分钟 | 屏幕变 `RESERVED` + 倒计时 |
| 2:00 | 到点后手机签到，输入屏上 4 位码 | 屏幕变 `CHECK IN` → 签到后 `IN USE` |
| 3:00 | 看后端日志 | `开锁指令已发布` → `收到回执 result=OK`（约 250ms） |
| 4:00 | 讲五步校验 | 见 6.3 的反向演示 |
| 6:00 | 断网演示 | 屏幕 `NO LINK`，恢复后自动回 `FREE` |

> 若预约返回"待审批"：是**当日自动通过已满 3 笔**（`E02_DAILY_LIMIT`），与信用分无关。
> 用 `admin01` 批准即可（教师账号没有审批权限）。

### 6.3 反向演示：篡改指令被拒

```python
import hmac, hashlib, json, uuid, datetime
secret = "demo-secret-room-a-please-change"
now = datetime.datetime.now().replace(microsecond=0)
issued  = now.strftime("%Y-%m-%dT%H:%M:%S")
expires = (now + datetime.timedelta(seconds=60)).strftime("%Y-%m-%dT%H:%M:%S")
mid = str(uuid.uuid4())
payload = "pulseMs=3000;reason=TAMPER"
canon = "1|%s|UNLOCK|ROOM-A-01|1|%s|%s|%s" % (mid, issued, expires, payload)
mac = hmac.new(secret.encode(), canon.encode(), hashlib.sha256).hexdigest()
payload += "X"      # 改了内容却不重签
print(json.dumps({"v":1,"msgId":mid,"type":"UNLOCK","deviceCode":"ROOM-A-01",
  "reservationId":1,"issuedAt":issued,"expiresAt":expires,
  "payload":payload,"hmac":mac}, separators=(',',':')))
```

```powershell
& "C:\Program Files\Mosquitto\mosquitto_pub.exe" -h 127.0.0.1 -u backend -P change-me `
  -t room/ROOM-A-01/cmd -q 1 -f tamper.json
```

设备蜂鸣三短声并回 `ERR_HMAC`；同一条重发得到 `ERR_DUP`。

### 6.4 时间窗口不够用怎么办

签到窗口是 `[开始, 开始+5min)`，讲慢了就废。后端支持整体平移"应用时间"：

```powershell
.\mvnw.cmd spring-boot:run "-Dspring-boot.run.profiles=local,mqtt-broker" `
  "-Dspring-boot.run.arguments=--app.clock.offset-minutes=-745"
```

偏移量 = 目标时刻 − 当前时刻（分钟，可为负）。例如 22:20 想让应用时间变 09:55 → **−745**。

> ⚠️ 两点：**板子必须断电重启**（设备时钟只向前校准，服务端往回跳它不跟随）；
> 用完立刻去掉参数重启，否则调度器会按偏移时间跑，可能把待开始的预约判成"过期未签到"。

## 7. 故障排查

| 现象 | 原因 | 处置 |
|---|---|---|
| 屏幕 `NO LINK`，串口 `CIPSTART failed` | Broker 没起 / IP 变了 / 热点没开 | 查 1883、查 `APP_BROKER_HOST` |
| 屏幕 `NO LINK`，串口 `AT no-OK` | 模块不在 AT 模式 | 断电重启整板（固件已在启动时发 `+++` 兜底） |
| 屏幕 `WAITING` | 连上了但没快照 | 后端是否起、profile 是否含 `mqtt-broker` |
| 串口无任何输出 | P3 跳线帽掉了 / 波特率不对 / 芯片停在 halt | 查跳线帽、115200、Keil 是否勾 Reset and Run |
| 屏幕全黑但背光逻辑正常 | I2C 接触不良 | 重插线；固件会退避 5 秒重试，不会卡死 |
| 签到提示"不在签到窗口" | 时间点没对上 | 重约下一格，或用 6.4 的偏移 + 重启板子 |
| 预约返回"待审批" | 当日自动通过满 3 笔 | `admin01` 批准，或 `/admin/rules` 调大上限 |
| 签到成功但门没动 | 锁未接 / 继电器没供电 | 万用表量 `PB0` 对 GND，应有 3 秒高电平 |
| 后端报 `MQTT 未连接，无法发布` | 启动瞬间的正常现象 | 连接建立后会自动补发，不必处理 |

**板子彻底不行时的兜底**：换纯软件模式，协议行为一致（同样的五步校验与回执），只是"锁"变成日志里的 `[LOCK]`：

```powershell
.\mvnw.cmd spring-boot:run "-Dspring-boot.run.profiles=local,mqtt-demo"
```

> "不能复核自己审核的申诉"）。演示申诉流程时用 `admin02` 去复核 `admin01` 的审核结果。
