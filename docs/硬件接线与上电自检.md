## 1. 接线表（照着一根一根接）

### 1.1 开发板自身（必查，不接线但决定能不能用）

| 位置 | 正确状态 | 说明 |
|---|---|---|
| `USB_UART`（Type-C 座） | 接电脑 USB | 既是 CH340 通信口，也是板子主供电口 |
| 电源开关 | 先保持 **OFF** | 静态检查完再合上 |
| P3（USART1↔CH340 选择） | `RXD`、`TXD` **两个跳线帽都在位** | 手册 §2.1.3：标号是相对 CH340 的；缺帽则 printf 无输出 |
| BOOT 跳线（B0/B1） | BOOT0 = 0（运行 Flash） | 用 flymcu 一键下载时电路会自动拉高 BOOT0；SWD 下载不受影响 |
| P9（CAN/USB 选择） | 不关心 | 本项目不用 USB/CAN，帽保持默认 |
| 调试口 | SWD：PA13(SWDIO) / PA14(SWCLK) / GND / 3.3V | **不要切 JTAG**：PA15 是 JTDI，与 GBC_LED 复用 |

### 1.2 SSD1306（4 针 I2C）

| 屏针脚 | 接到开发板 | 备注 |
|---|---|---|
| VCC | 3.3V 排针（VOUT1） | **3.3V，不是 5V** |
| GND | 板 GND | 必须与板共地 |
| SCL | **PB6** | 与板载 24C02 共 I2C1 总线 |
| SDA | **PB7** | 同上 |

> **不要插 P4**：手册 §2.1.19 的 P4 是 OLED/**摄像头并行**接口（SCL/SDA 走 PD3/PG13，数据走 PC0~7），和 4 针 I2C 屏不是一种东西。屏正常时 I2C 扫描会看到 `0x3C`（屏）和 `0x50`（24C02）两个地址，这是正常的。

### 1.3 ESP8266 模块

| 项 | 做法 |
|---|---|
| 安装 | 插到 ATK-MODULE 座 **U3（1×6 排座）**，按模块与座子丝印方向插入，不要硬怼 |
| 供电 | 用板上 3.3V（U3 座已提供），不外接 LDO |
| 串口 | U3 的 GBC_RX/GBC_TX 已接 PB10/PB11，无需飞线 |
| RST / EN | **不接**——U3 只引 TX/RX/KEY/LED，没有 RST/EN；模块复位由自身电路完成 |
| 天线 | 远离金属外壳和 12V 锁线束 |

### 1.4 蜂鸣器与锁

| 器件 | 本次接法 |
|---|---|
| 板载蜂鸣器 | **不用接线**，PB8 控制，高电平响；R33 下拉保证复位时不误响 |
| 外接有源蜂鸣器（备用） | 暂不接。真要用：GPIO → 驱动管（如 AO3400）→ 蜂鸣器 → 5V，共地；控制脚用 PB1（未插 LCD 时可用） |
| 12V 电控锁 | **本次不接**。预留：PB0 → 逻辑电平 MOSFET 栅极，线圈并 1N4007 续流，12V 独立电源只与板共地 |

## 2. 通电前的静态检查（万用表，全部断电做）

| # | 测哪里 | 正常结果 | 不正常意味着 |
|---|---|---|---|
| 1 | 3.3V 排针对 GND（电阻档） | 刚接触可能有短暂蜂鸣（电容充电），随后电阻上升；**不能稳定接近 0Ω** | 3.3V 对地短路，禁止上电 |
| 2 | 5V 对 GND | 同上，不能稳定 0Ω | 5V 短路 |
| 3 | 3.3V 与 5V 之间 | 高阻，不能 0Ω | 两个电源被短接 |
| 4 | PB6、PB7 分别对 GND | 不能 0Ω（有 24C02 与屏的上拉电阻） | I2C 总线对地短路 |
| 5 | OLED 的 VCC/GND 是否接反 | 逐根对照线色/针脚 | 接反上电即烧屏 |
| 6 | 8266 是否插反、针脚是否跨座 | 每个针脚都落在座孔内 | 轻则不通，重则倒灌烧模块 |
| 7 | 板上是否有裸露导线搭到相邻排针 | 目视无 | 上电可能烧 IO |

> 第 1/2 项用蜂鸣档时"响一下就停"是正常的（去耦电容充电）；**持续蜂鸣**才是短路。

## 3. 上电自检（按顺序，每项通过再进下一项）

### 3.1 只给板子供电（暂不装模块、不接屏）

1. 合上电源开关，蓝色 **PWR** 灯应常亮（手册 §2.1.18）。
2. 万用表量 3.3V 排针：应在 **3.2~3.4V**；量 5V 网络约 5V。
3. 摸一下 3.3V 稳压芯片：微温正常，**烫手立刻断电**。
4. 板上红色 LED0(PB5)、绿色 LED1(PE5) 此时**不亮**是正常的——没有固件。

### 3.2 USB 串口通路

1. 设备管理器应出现 **CH340** 的 COM 口；没有就装驱动或换数据线。
2. 串口助手设 **115200 / 8N1**，先不开串口也行。
3. 可选环回测试：断电取下 P3 的两个跳线帽，把 **CH340 侧**的 RXD/TXD 短接，上电后打开串口助手发任意字符应原样回显；测完恢复跳线帽。**注意短的是 CH340 那一侧，不是 MCU 的 PA9/PA10。**
4. 恢复 P3 后，没有固件时串口无输出是正常的。

> 模板工程已有编译好的 `MDK-ARM/AIOT_Device_STM32F103_WIFI/AIOT_Device_STM32F103_WIFI.hex`，可以拿来快速验证供电与 printf。但它的 `main.c` 第 301 行在 `ATK_MW8266_detect()` 失败时会 `while(1)` 停住，**没插 8266 / 没配好 WiFi 时停在这里不代表板子坏了**。

### 3.3 装 ESP8266

1. **断电**插入 U3 座。
2. 上电，模块电源指示灯应亮；3.3V 电压不应被拉到 3.0V 以下。
3. 若模块处于 AP 模式，手机 WiFi 列表能扫到它的热点；扫不到也不一定坏（可能已是 STA 模式）。
4. 有 USB-TTL 的话可单独把模块接电脑做 `AT` → `AT+GMR` 测试（115200）；**没有就跳过，等固件做 AT 透传测试**。不要为了测 AT 去动 PB12/PB13。

### 3.4 装 SSD1306

1. **断电**接 4 根线，逐根再核对一次 VCC/GND。
2. 上电后屏不亮是正常的（没有初始化命令）；摸屏背板和排线应不发热。
3. 真正验证要等固件跑 I2C 扫描：期望看到 `0x3C` 与 `0x50`。

### 3.5 蜂鸣器（板载）

1. 上电瞬间不应持续响——R33 下拉起作用。
2. 如果一上电就长鸣：断电检查 PB8 是否被外部接到 3.3V，或板子是否残留了其他固件。
3. PB8 置高 100ms 响一声的验证放到固件自检项里做。

## 6. 故障速查

| 现象 | 最可能原因 | 处理 |
|---|---|---|
| PWR 灯不亮 | 电源开关未合 / USB 线只有充电线 / USB 口接触不良 | 换数据线、查开关 |
| 3.3V 只有 2.x V | 8266 发射瞬间拉低、供电不足 | 换 DC 6~15V 输入；USB 供电时 3.3V 排针上限 500mA |
| CH340 找不到 | 驱动未装 / 线材问题 | 装 CH340 驱动，换线 |
| printf 无输出 | P3 跳线帽缺失 / 波特率不对 | 补帽、设 115200 |
| 一上电长鸣 | PB8 被外部拉高或残留固件 | 断电查 PB8 接线 |
| I2C 扫不到 0x3C | 屏接错线 / 插到 P4 / VCC 接成 5V | 逐根核对 PB6/PB7 与 3.3V |
| 只看到 0x50 | OLED 没上电或 SCL/SDA 接反 | 量屏 VCC，换 SCL/SDA |
| 8266 无 `AT` 回应 | 波特率不是 115200 / 模块在透传模式 / 插反 | 先发 `+++` 退透传，再查方向 |
| 按键无反应 | PA0 配成了上拉+下降沿（v3 旧配置） | 改下拉 + **上升沿** |
| 下载失败 | BOOT0 被跳线固定为 1 / 选错芯片型号 | BOOT0=0，芯片选 STM32F103ZETx |
